# 缓存重复抓取问题排查指南

## 🐛 问题现象

批量采集时，明明已经抓取过的比赛还在重复抓取，没有跳过。

---

## 🔍 可能原因

### 1. 缓存检查被禁用

前端传参 `skip_cached: false`，导致不检查缓存。

### 2. 缓存键不匹配

保存时和检查时生成的文件名不一致，导致找不到缓存文件。

**常见原因**:

- 队伍名称格式不同（全角/半角、空格/下划线等）
- 时间格式不同（`2025-11-15 13:00` vs `13:00`）
- 联赛名称不同或缺失

### 3. 缓存目录结构变化

- 旧结构: `data/YYYY-MM-DD/文件名.json`
- 新结构: `data/YYYY/MM/DD/文件名.json`

如果保存在新结构，但检查时只看旧结构，会找不到。

### 4. 文件名特殊字符处理

队伍名中的特殊字符（`/`, `:`, `*` 等）被替换成不同的字符。

## ✅ 解决方案

### 方案 1：统一字段名

如果发现 match 对象使用的字段名不一致，修改 `_generate_cache_key()`：

```python
# detail_cache_manager.py
def _generate_cache_key(self, match_info: Dict) -> Tuple[str, str]:
    # 提取日期 - 支持多种字段名
    kickoff = (
        match_info.get('kickoff') or
        match_info.get('match_time') or
        match_info.get('time') or
        ''
    )

    # 提取队伍 - 支持多种字段名
    home = (
        match_info.get('home') or
        match_info.get('home_team') or
        'H'
    )
    away = (
        match_info.get('away') or
        match_info.get('away_team') or
        'A'
    )
```

### 方案 2：标准化队伍名称

添加队伍名称标准化函数：

```python
def _normalize_team_name(self, name: str) -> str:
    """标准化队伍名称"""
    # 全角转半角
    name = name.replace('　', ' ')  # 全角空格
    # 去除多余空格
    name = ' '.join(name.split())
    # 统一替换特殊字符
    for char in ['/', '\\', ':', '*', '?', '"', '<', '>', '|']:
        name = name.replace(char, '_')
    # 空格改为下划线
    name = name.replace(' ', '_')
    return name.strip()
```

### 方案 3：强制重新抓取

如果临时需要忽略缓存，前端传参：

```javascript
fetch("/api/collect/batch_range_stream", {
  method: "POST",
  body: JSON.stringify({
    start_date: "2025-11-15",
    skip_cached: false, // 不跳过缓存，强制重新抓取
  }),
});
```

### 方案 4：清理错误缓存

如果发现某些缓存文件格式错误，可以手动删除：

```python
# 使用API清理
POST /api/clear_caches
{
  "cache_keys": ["2025-11-15/2025-11-15_韩K联_FC首尔_vs_江原FC_1300"]
}
```

## 💡 常见问题

### Q1: 为什么有的比赛跳过了，有的没跳过？

**A**: 可能是不同来源的比赛数据，字段名不一致。

**解决**:

1. 查看日志中的 "原始数据" 字段
2. 对比跳过和未跳过的比赛字段差异
3. 修改 `_generate_cache_key()` 兼容所有字段名

### Q2: 明明文件存在，为什么还显示 "无缓存"？

**A**: 可能原因：

1. 文件名不完全匹配（多/少空格、下划线等）
2. 文件在旧目录结构，但检查新结构
3. 联赛名称有/无的差异

**解决**:

1. 启用 DEBUG 日志，查看生成的完整路径
2. 手动检查该路径文件是否存在
3. 对比实际文件名和生成的文件名

### Q3: 如何批量清理所有缓存重新抓取？

**A**:

```bash
# 方法1: API
POST /api/clear_all_caches

# 方法2: 手动删除
rm -rf d:\MSM\Cursor\football\data\2025\
```

1. **统一数据源格式**

