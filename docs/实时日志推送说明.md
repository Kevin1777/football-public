# 实时日志推送功能说明

## 🎯 功能目标

**将后端日志（包括验证码登录信息）实时推送到前端页面**

## ✅ 已实现功能

### 1. 日志流处理器

创建了 `LogStreamHandler` 来捕获后端日志：

```python
# utils/log_stream_handler.py
class LogStreamHandler(logging.Handler):
    """捕获日志消息并存储到队列"""

    def start_capture(self):
        """开始捕获日志"""

    def get_messages(self):
        """获取捕获的消息"""
```

### 2. 自动推送机制

在采集过程中自动推送后端日志：

- ✅ 验证码识别成功/失败
- ✅ 登录状态检查
- ✅ OCR 识别详情
- ✅ 网络错误信息

### 3. 前端实时显示

前端自动处理 `log` 类型消息：

```javascript
case "log":
  appendLog(data.message, data.log_type);
  break;
```

## 工作原理

### 1. 日志捕获

```
后端logger.info()
    ↓
LogStreamHandler捕获
    ↓
存储到队列
```

### 2. 日志推送

```
采集过程中
    ↓
定期调用 push_backend_logs()
    ↓
通过SSE推送到前端
    ↓
前端实时显示
```

### 3. 消息格式

```json
{
  "type": "log",
  "level": "INFO",
  "log_type": "info",
  "message": "✅ OCR识别成功: '8139'",
  "timestamp": "2025-11-21T12:17:10"
}
```

## 性能影响

### 内存使用

- 队列最大 100 条消息
- 自动淘汰旧消息
- 影响极小（<1MB）

### 推送频率

- 每次获取比赛列表后推送一次
- 避免频繁推送（影响性能）
- 批量推送多条日志

## 最佳实践

### ✅ 推荐做法

1. **保持日志简洁**

   - 只记录关键信息
   - 避免过多调试日志

2. **及时清空**

   - 每次推送后自动清空队列
   - 避免重复推送

3. **合理的推送时机**
   - 在关键操作后推送
   - 不要每条日志都立即推送

### ⚠️ 注意事项

1. **不要推送敏感信息**

   - 密码、Token 等
   - 用户隐私数据

2. **控制日志数量**

   - 避免日志爆炸
   - 设置合理的队列大小

3. **性能考虑**
   - 大量日志时分批推送
   - 避免阻塞主流程

## 故障排查

### Q1: 前端看不到后端日志？

**检查**:

1. 日志捕获是否启动
2. `log_stream.enabled` 是否为 `true`
3. 前端是否处理了 `log` 类型消息

**解决**:

```python
# 确保启动了捕获
log_stream.start_capture()
```

### Q2: 日志重复？

**原因**: 没有及时清空队列

**解决**:

```python
# 每次推送后清空
log_stream.clear()
```

### Q3: 日志丢失？

**原因**: 队列满了，旧消息被淘汰

**解决**:

```python
# 增加队列大小
log_stream = LogStreamHandler(max_messages=200)
```
