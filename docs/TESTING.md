# Testing and verification

## 默认离线检查

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
python tools/check_public_release.py
```

`pytest.ini` 明确列出核心测试文件：特征提取、评分、动态阈值、混合推荐、类型选择、结果验证、格式化和离线演示。使用现有属性测试与场景测试，不遍历全部旧脚本。

离线演示测试还会在禁止创建 socket 的情况下生成报告，检查输出、预设结果覆盖和 HTML 转义。示例数据中的预测方向与比分来自固定样例，不能作为模型预测能力的证据。

## CI

[ci.yml](../.github/workflows/ci.yml) 在 Windows / Ubuntu 与 Python 3.11 / 3.12 的四种组合运行：

1. 安装独立开发依赖，不安装整套 Web / 浏览器 / OCR 依赖。
2. 执行默认离线测试。
3. 生成合成演示报告。
4. 解析所有 Git 跟踪的 Python 源码，检查禁止发布的运行文件与精确凭据特征，并用 detect-secrets 扫描跟踪文本。

CI 只验证运行对应提交的这些检查；以 Actions 中真实状态为准。仓库状态徽章链接到实际工作流。

## 为什么不直接运行整个 tests 目录

旧目录中混有单元测试、手动诊断脚本和在线集成脚本。有些会访问数据源、打开浏览器、调用本机 API 或发送通知。没有授权账号和明确测试目标时，不能当作通用离线测试运行。直接运行 `pytest tests/` 会绕开默认文件列表，不是推荐的验证命令。
