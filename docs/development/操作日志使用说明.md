# 操作日志使用说明

## 概述

系统已集成操作日志功能，所有运行日志会自动保存到文件，便于问题排查和回溯。

### 核心特性

- ✅ **自动轮转**：每 48 小时自动轮转一次
- ✅ **压缩存储**：归档日志自动压缩（.gz 格式）
- ✅ **自动清理**：保留最近 7 天的日志，超期自动删除
- ✅ **全模块覆盖**：app、推送系统、爬虫客户端等所有模块日志都会记录
- ✅ **API 查询**：提供丰富的 API 接口查看和搜索日志

## 日志文件结构

```
football/
├── logs/
│   ├── football_current.log          # 当前日志文件（实时写入）
│   └── archive/                       # 归档目录
│       ├── football_20251125_100000.log.gz  # 已归档的日志（压缩）
│       ├── football_20251123_100000.log.gz
│       └── ...
```

### 文件说明

| 文件                   | 说明             | 大小限制            |
| ---------------------- | ---------------- | ------------------- |
| `football_current.log` | 当前活动日志     | 无限制              |
| `archive/*.log.gz`     | 归档日志（压缩） | 自动清理超过 7 天的 |

## 自动轮转机制

### 轮转触发

每 48 小时自动触发一次轮转：

```
当前时间 = 2025-11-25 22:00
上次轮转 = 2025-11-23 22:00
距离时间 = 48小时

→ 触发轮转:
  1. 当前日志重命名为 football_20251125_220000.log
  2. 压缩为 football_20251125_220000.log.gz
  3. 创建新的 football_current.log
```

### 自动清理

每次轮转时检查并清理超过 7 天的归档：

```
今天 = 2025-11-25
保留截止 = 2025-11-18

→ 删除 < 2025-11-18 的所有归档日志
```

## API 接口

### 1. 查看最近日志

**请求：**

```bash
GET /api/logs/view?lines=500
```

**参数：**

- `lines`: 要查看的最后 N 行（默认 500）

**响应示例：**

```json
{
  "success": true,
  "lines": 500,
  "content": "2025-11-25 22:00:00 - app - INFO - 服务启动\n..."
}
```

**用途：**

- 快速查看最近的运行日志
- 检查当前系统状态

### 2. 获取日志统计

**请求：**

```bash
GET /api/logs/stats
```

**响应示例：**

```json
{
  "success": true,
  "stats": {
    "current_log_size": 1048576,
    "current_log_size_mb": 1.0,
    "current_log_lines": 5234,
    "archive_count": 5,
    "total_archive_size": 2097152,
    "total_archive_size_mb": 2.0,
    "oldest_archive": "2025-11-18 22:00:00",
    "newest_archive": "2025-11-23 22:00:00"
  }
}
```

**用途：**

- 监控日志文件大小
- 查看归档数量
- 了解最早可追溯的日志时间

### 3. 搜索日志内容

**请求：**

```bash
POST /api/logs/search
Content-Type: application/json

{
  "keyword": "推送",
  "max_results": 100
}
```

**响应示例：**

```json
{
  "success": true,
  "keyword": "推送",
  "total": 23,
  "results": [
    {
      "file": "current",
      "line_num": 1234,
      "content": "2025-11-25 21:25:00 - auto_recommend_push - INFO - 执行赛前推送..."
    },
    {
      "file": "football_20251123_220000.log.gz",
      "line_num": 567,
      "content": "2025-11-23 21:30:00 - auto_recommend_push - INFO - 推送完成"
    }
  ]
}
```

**用途：**

- 查找特定事件的日志
- 追溯历史问题
- 统计某类操作的频率

### 4. 手动触发轮转

**请求：**

```bash
POST /api/logs/rotate
```

**响应示例：**

```json
{
  "success": true,
  "message": "日志已成功轮转"
}
```

**用途：**

- 在需要时手动归档当前日志
- 清空当前日志文件

## 使用场景

### 场景 1：排查推送失败问题

**步骤：**

1. **搜索关键字**

```bash
curl -X POST http://localhost:5000/api/logs/search \
  -H "Content-Type: application/json" \
  -d '{"keyword": "推送失败", "max_results": 50}'
```

2. **查看详细日志**

```bash
curl http://localhost:5000/api/logs/view?lines=1000
```

3. **定位错误时间点**
   - 从搜索结果中找到失败的时间
   - 在详细日志中查看前后的上下文

### 场景 2：监控系统健康

**定期检查日志统计：**

```bash
curl http://localhost:5000/api/logs/stats
```

**关注指标：**

- `current_log_size_mb`: 如果超过 100MB，考虑手动轮转
- `archive_count`: 归档数量反映系统运行时长
- `current_log_lines`: 行数过多说明日志输出频繁

### 场景 3：调查历史问题

**示例：查找某天的推送记录**

1. 搜索关键日期和关键字：

```bash
curl -X POST http://localhost:5000/api/logs/search \
  -H "Content-Type: application/json" \
  -d '{"keyword": "2025-11-23 21:25", "max_results": 100}'
```

2. 结果会包含当前日志和归档日志中的所有匹配项

### 场景 4：清理日志空间

**手动触发轮转：**

```bash
curl -X POST http://localhost:5000/api/logs/rotate
```

**效果：**

- 当前日志归档并压缩
- 创建新的空白日志文件
- 自动清理超过 7 天的旧归档

## 配置参数

如需修改配置，在 `utils/operation_logger.py` 中调整：

```python
class OperationLogger:
    def __init__(self, log_dir: str = "logs", app_name: str = "football"):
        # 可修改的参数
        self.rotation_hours = 48  # 轮转周期（小时）
        self.keep_days = 7        # 保留天数
```

### 常用配置

| 场景     | rotation_hours | keep_days |
| -------- | -------------- | --------- |
| 日志较少 | 72 (3 天)      | 14 天     |
| 默认配置 | 48 (2 天)      | 7 天      |
| 日志频繁 | 24 (1 天)      | 3 天      |

## 注意事项

1. **日志文件占用空间**

   - 当前日志不限大小，如果过大可手动轮转
   - 归档日志会压缩，通常能减少 70-80%空间

2. **搜索性能**

   - 搜索会遍历当前日志和所有归档
   - 如果归档很多，搜索会比较慢
   - 建议限制 `max_results` 参数

3. **日志轮转时机**

   - 自动轮转在 48 小时整点触发
   - 手动轮转会立即执行
   - 轮转时不会丢失任何日志

4. **归档解压**
   - API 搜索会自动解压归档
   - 手动解压需要支持 gzip 的工具

## 常见问题

### Q1: 为什么看不到日志文件？

- 检查 `logs/` 目录是否存在
- 确认服务已启动（日志在启动时才创建）

### Q2: 日志文件太大怎么办？

- 手动触发轮转：`POST /api/logs/rotate`
- 或直接删除归档目录中的旧文件

### Q3: 如何查看特定时间的日志？

1. 确认该时间是否在保留期内（7 天）
2. 使用搜索 API，输入时间关键字
3. 或手动解压对应的归档文件

### Q4: 日志轮转会影响服务吗？

- 不会，轮转过程是无缝的
- 新日志会立即写入新文件
- 不会有日志丢失
