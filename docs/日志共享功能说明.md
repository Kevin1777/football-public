# 日志共享功能说明

## 🎯 核心需求

**场景**: 服务器在 tmux 中运行采集，其他设备后来访问页面时，能看到之前的采集日志历史。

## ✅ 已实现功能

### 1. 日志持久化

所有采集日志自动保存到文件：

```
logs/session_20251121_120000.log
```

### 2. 历史日志加载

新设备访问页面时：

1. 自动加载最近 100 条日志
2. 重放所有历史消息
3. 显示当前采集进度

### 3. 实时同步

- 服务器端记录每条 SSE 消息
- 新设备加载历史后继续接收新消息
- 多设备看到相同的日志

## 使用场景

### 场景 1: tmux 后台运行

```bash
# 服务器上
tmux new -s collect
python app.py

# 开始采集
# Ctrl+B, D 分离会话
```

**其他设备访问**:

1. 打开 http://服务器 IP:5001/collect
2. 自动加载历史日志
3. 看到服务器上的采集进度
4. 实时同步新的日志

### 场景 2: 多人协作

**用户 A** (在服务器旁):

- 开始日期区间采集
- 看到实时日志

**用户 B** (远程):

- 15 分钟后访问页面
- 自动看到前 15 分钟的日志
- 了解当前采集到哪了

### 场景 3: 断线恢复

**步骤**:

1. 开始采集
2. 网络断开/关闭浏览器
3. 重新打开页面
4. 自动加载所有历史日志
5. 继续查看采集进度

## API 接口

### 获取日志历史

```bash
# 获取最近100条日志
GET /api/collect/logs?limit=100

# 获取指定会话的日志
GET /api/collect/logs?session_id=20251121_120000&limit=200
```

**响应示例**:

```json
{
  "success": true,
  "messages": [
    {
      "type": "phase",
      "phase": 1,
      "message": "第一阶段：扫描 21 天",
      "timestamp": "2025-11-21T12:00:00",
      "session_id": "20251121_120000"
    },
    {
      "type": "scan_result",
      "date": "2025-11-15",
      "matches": 16,
      "timestamp": "2025-11-21T12:00:05"
    }
  ],
  "count": 100,
  "active_session": "20251121_120000"
}
```

## 前端实现

### 页面加载时

```javascript
window.addEventListener("DOMContentLoaded", async () => {
  // 1. 加载历史日志
  await loadHistoryLogs();

  // 2. 检查采集状态
  await checkCollectionStatus();
});
```

### 历史日志重放

```javascript
async function loadHistoryLogs() {
  const response = await fetch("/api/collect/logs?limit=100");
  const data = await response.json();

  if (data.success && data.messages.length > 0) {
    appendLog(`📚 加载历史日志 (${data.messages.length} 条)...`);

    // 重放每条消息
    data.messages.forEach((msg) => {
      handleSSEMessage(msg); // 复用SSE消息处理函数
    });

    appendLog(`✅ 历史日志加载完成`);
  }
}
```

### ✅ 断线恢复

### ✅ 后台运行

### ✅ 协作友好

多人可以同时查看采集进度，了解任务状态。

## 注意事项

### 1. 日志文件大小

- 默认保留最近 500 条消息在内存
- 文件持久化所有消息
- 定期清理 7 天前的日志

### 2. 性能影响

- 每条消息写入文件（异步 IO）
- 影响很小（通常<1ms）
- 适合中等规模采集

### 3. 并发访问

- 多设备同时读取日志文件
- 文件系统支持并发读
- 无锁竞争问题

## 日志管理

### 查看日志文件

```bash
# 查看指定会话的日志
cat logs/session_20251121_120000.log

# 实时查看正在写入的日志
tail -f logs/session_20251121_120000.log

# 统计日志行数
wc -l logs/session_*.log
```

### 清理旧日志

**自动清理**:

```python
# 每次启动时自动清理7天前的日志
log_manager.cleanup_old_logs(days=7)
```

**手动清理**:

```bash
# 删除7天前的日志
find logs/ -name "session_*.log" -mtime +7 -delete
```

### 备份日志

```bash
# 备份到其他位置
tar -czf logs_backup_$(date +%Y%m%d).tar.gz logs/

# 上传到云存储
rclone copy logs/ remote:logs/
```

## 故障排查

### Q1: 历史日志没有加载？

**检查**:

```bash
# 1. 确认日志文件存在
ls -lh logs/

# 2. 检查API是否正常
curl http://localhost:5001/api/collect/logs?limit=10

# 3. 查看浏览器控制台
F12 → Console
```

### Q2: 日志丢失？

**可能原因**:

- 服务器异常崩溃（未正常写入）
- 磁盘空间不足
- 权限问题

**解决**:

```bash
# 检查磁盘空间
df -h

# 检查目录权限
ls -ld logs/

# 查看服务器日志
tail -f app.log | grep "日志"
```

### Q3: 日志太多导致加载慢？

**优化**:

```javascript
// 减少加载数量
await fetch("/api/collect/logs?limit=50"); // 改为50条

// 或只加载特定会话
await fetch("/api/collect/logs?session_id=XXX&limit=100");
```
