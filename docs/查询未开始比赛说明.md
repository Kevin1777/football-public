# 🔮 查询未开始比赛功能说明

## 🎯 功能目标

**支持查询未来的比赛（未开始的比赛），用于提前分析和准备**

## ✅ 已实现功能

### 1. 后端支持

在 `BifawClient.fetch_match_list_v2()` 中添加了 `future_days` 参数：

```python
def fetch_match_list_v2(
    self,
    *,
    rows: int = 200,
    days: int = 2,           # 查询过去多少天
    future_days: int = 0,    # 🔥 查询未来多少天
    force_refresh: bool = False
) -> List[Dict[str, Optional[str]]]:
```

### 2. 查询逻辑

```python
# 查询日期范围：过去 + 今天 + 未来
date_list = []

# 添加过去的日期
for delta in range(days):
    date_list.append(today - timedelta(days=delta))

# 添加未来的日期
for delta in range(1, future_days + 1):
    date_list.append(today + timedelta(days=delta))
```

### 3. API 接口

**端点**: `/api/bifaw/matches`

**新增参数**:

- `future_days`: 查询未来多少天（默认 0=不查未来）

**示例**:

```bash
# 查询今天+未来2天的比赛
GET /api/bifaw/matches?future_days=2

# 查询今天+昨天+未来3天的比赛
GET /api/bifaw/matches?days=2&future_days=3

# 查询未来一周的比赛
GET /api/bifaw/matches?days=1&future_days=7
```

### 4. 前端界面

在"选择标盘场次"区域添加了下拉选择框：

```
┌─────────────────────────────────┐
│ 查询未来 [下拉选择框] ▼         │
│   ├─ 0天（不查未来）  ← 默认     │
│   ├─ 1天（今天+明天）           │
│   ├─ 2天（今天+后2天）          │
│   ├─ 3天（今天+后3天）          │
│   └─ 7天（今天+未来一周）       │
└─────────────────────────────────┘
```

## 📖 使用方法

### 方法 1: 使用前端界面

1. **打开采集页面**

   ```
   http://localhost:5001
   ```

2. **设置未来天数**

   - 找到"查询未来"下拉框
   - 选择需要查询的未来天数（如：2 天）

3. **点击"获取场次"**

   - 系统会查询过去+今天+未来的比赛
   - 显示所有符合条件的比赛列表

4. **查看结果**
   - 比赛列表会显示所有查询到的比赛
   - 包括未开始的比赛

### 方法 2: 使用 API

```bash
# 查询未来3天的比赛
curl "http://localhost:5001/api/bifaw/matches?future_days=3"

# 查询今天+昨天+未来7天的比赛
curl "http://localhost:5001/api/bifaw/matches?days=2&future_days=7"

# 查询未来比赛并过滤盘口
curl "http://localhost:5001/api/bifaw/matches?future_days=3&filter_by_handicap=1"
```

## 💡 应用场景

### 场景 1: 提前分析

**需求**: 查看明天有哪些比赛，提前准备分析

**操作**:

1. 设置"查询未来"为 1 天
2. 点击"获取场次"
3. 查看明天的比赛列表

### 场景 2: 周末比赛准备

**需求**: 查看本周末的比赛

**操作**:

1. 设置"查询未来"为 3-7 天
2. 点击"获取场次"
3. 筛选周末的比赛

### 场景 3: 完整赛程查看

**需求**: 查看过去+今天+未来的所有比赛

**操作**:

1. 设置"查询未来"为 7 天
2. 默认会查询过去 2 天
3. 总共查询：过去 2 天+今天+未来 7 天

## ⚙️ 参数说明

### days (查询过去天数)

| 值  | 说明         | 查询范围         |
| --- | ------------ | ---------------- |
| 0   | 只查今天     | 今天             |
| 1   | 今天+昨天    | 昨天、今天       |
| 2   | 今天+前 2 天 | 前天、昨天、今天 |
| 7   | 今天+前 7 天 | 过去一周         |

### future_days (查询未来天数)

| 值  | 说明      | 查询范围           |
| --- | --------- | ------------------ |
| 0   | 不查未来  | -                  |
| 1   | 明天      | 明天               |
| 2   | 未来 2 天 | 明天、后天         |
| 3   | 未来 3 天 | 明天、后天、大后天 |
| 7   | 未来一周  | 未来 7 天          |

## 🔍 查询结果

### 比赛状态标识

查询到的比赛可能处于不同状态：

| 状态   | 说明         | 特征           |
| ------ | ------------ | -------------- |
| 未开始 | 比赛尚未开始 | 开球时间在未来 |
| 进行中 | 比赛正在进行 | 滚球状态       |
| 已完场 | 比赛已结束   | 有最终比分     |

### 数据完整性

- ✅ **未开始比赛**: 可以看到盘口数据，但没有比赛明细
- ✅ **进行中比赛**: 可以看到实时盘口变化
- ✅ **已完场比赛**: 可以采集完整明细数据

## ⚠️ 注意事项

### 1. 未开始比赛的限制

- **没有明细数据**: 未开始的比赛无法采集明细（没有历史投注数据）
- **只有盘口数据**: 可以查看开盘盘口
- **需要等待开赛**: 等比赛开始后才能采集明细

### 2. 数据可用性

```
未开始比赛：
  ✅ 基本信息（队伍、时间、联赛）
  ✅ 开盘盘口
  ❌ 比赛明细（需等开赛）
  ❌ 历史投注数据

进行中比赛：
  ✅ 基本信息
  ✅ 实时盘口
  ✅ 部分比赛明细
  ⚠️ 数据仍在变化

已完场比赛：
  ✅ 所有数据完整
```

### 3. 查询频率

- 未来比赛数据相对固定，不需要频繁刷新
- 建议每小时刷新一次即可
- 接近开赛时间可以增加刷新频率

## 🎯 最佳实践

### ✅ 推荐做法

1. **提前查看**

   - 每天早上查看未来 3 天的比赛
   - 挑选感兴趣的比赛

2. **定时刷新**

   - 未来比赛每小时刷新一次
   - 今天的比赛每 10 分钟刷新一次

3. **分类管理**
   - 未开始：用于分析准备
   - 进行中：用于实时跟踪
   - 已完场：用于数据采集

### ⚠️ 避免事项

1. **不要频繁刷新未来比赛**

   - 数据变化不大
   - 浪费资源

2. **不要采集未开始比赛的明细**

   - 会失败（没有数据）
   - 等比赛开始后再采集

3. **注意盘口变化**
   - 未开始比赛的盘口可能调整
   - 以开赛前最终盘口为准

## 🐛 故障排查

### Q1: 未来比赛查询为空？

**可能原因**:

1. 选择的 future_days 为 0
2. 必发网站未发布未来比赛
3. 网络问题

**解决方案**:

```bash
# 检查参数
future_days=3  # 确认不为0

# 检查网络
curl "http://localhost:5001/api/bifaw/matches?future_days=3"

# 查看日志
# 确认是否有错误信息
```

### Q2: 查询到的比赛没有明细？

**原因**: 未开始的比赛没有明细数据

**正常行为**: 这是预期的，需要等比赛开始后才能采集明细

### Q3: 查询很慢？

**可能原因**:

- future_days 设置太大（如 30 天）
- 网络延迟

**解决方案**:

- 减小 future_days（建议 ≤7 天）
- 使用缓存（不要每次都 refresh=1）

## 📊 数据流程

```
用户选择未来天数
    ↓
前端发送API请求
    ↓
后端构造日期列表
    ↓
循环查询每个日期
    ├─ 过去的日期（days）
    ├─ 今天
    └─ 未来的日期（future_days）
    ↓
合并所有结果
    ↓
返回给前端显示
```
