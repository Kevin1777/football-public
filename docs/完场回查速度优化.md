# 完场回查速度优化

## 🐌 原有问题

### 速度慢的原因

1. **Selenium 捕获链接慢**：尝试捕获 100 个按钮，需要 30-40 秒
2. **每次都重新查询**：没有缓存机制，重复查询浪费时间
3. **无超时机制**：Selenium 卡住时会一直等待

### 原有性能

```
Selenium捕获(30-40秒) + API查询(2-3秒) = 32-43秒 ❌
```

## ✅ 优化方案

### 1. 减少 Selenium 捕获数量

**优化前**：

```python
max_buttons=100  # 捕获100个，耗时30-40秒
```

**优化后**：

```python
max_buttons=30   # 只捕获30个，耗时10-15秒
```

**理由**：

- 大多数用户只需要看最近的几场比赛
- 30 场已经足够覆盖一天的主要比赛
- 速度提升 **60%** ⚡

### 2. 添加超时机制

**优化前**：

```python
real_url_map = self._capture_finished_match_urls(driver, target_date)
# 如果卡住会一直等待
```

**优化后**：

```python
with concurrent.futures.ThreadPoolExecutor() as executor:
    future = executor.submit(capture_urls)
    try:
        real_url_map = future.result(timeout=15)  # 15秒超时
    except concurrent.futures.TimeoutError:
        print("⚠️ Selenium捕获超时，将使用备用方案")
        real_url_map = {}
```

**优势**：

- ✅ 避免无限等待
- ✅ 超时后使用备用 URL 构造方案
- ✅ 即使 Selenium 失败，仍能返回结果

### 3. 添加缓存机制

**优化前**：

```python
# 每次都重新查询
matches = fetch_from_api()  # 每次15-20秒
```

**优化后**：

```python
# 检查缓存（5分钟有效期）
date_key = target_date.strftime("%Y-%m-%d")
if date_key in self._finished_matches_cache:
    cached_matches, cached_time = self._finished_matches_cache[date_key]
    cache_age = time.time() - cached_time
    if cache_age < 300:  # 5分钟内
        print(f"✅ 使用缓存数据（{cache_age:.0f}秒前）")
        return cached_matches  # 瞬间返回 ⚡

# 查询并缓存
matches = fetch_from_api()
self._finished_matches_cache[date_key] = (matches, time.time())
```

**优势**：

- ✅ **第二次查询瞬间返回**（<1 秒）
- ✅ 5 分钟缓存适合快速浏览多场比赛
- ✅ 减轻服务器压力
