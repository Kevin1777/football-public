# 登录并发冲突修复完成

## 🔴 严重问题

### 用户反馈

> "当我在手动输入验证码的时候后台也在进行 OCR 登录，OCR 识别失败了就刷新了验证码，导致我手动也无法进行登录"

### 问题分析

从日志可见：

```
00:08:02 - OCR自动登录尝试
00:08:03 - 登录失败，刷新验证码 ❌
00:08:04 - 再次尝试，刷新验证码 ❌
... 持续刷新 ...
```

**并发冲突场景**：

```
时间线:
00:00 - 用户点击"获取验证码"
00:01 - 用户查看验证码图片
00:02 - 用户开始输入验证码
00:03 - [同时] OCR自动登录启动
00:04 - OCR识别失败 → 刷新验证码 ❌
00:05 - 用户输入完成，点击登录
00:06 - 用户登录失败（验证码已被刷新）❌
```

**根本原因**：

- 手动登录和 OCR 自动登录**没有互斥机制**
- 两个流程可以同时操作同一个登录会话
- OCR 刷新验证码会使用户输入失效

---

## ✅ 解决方案

### 核心机制：登录互斥锁

```python
# 新增字段
self._login_in_progress = False  # 登录进行中标记
self._login_lock = threading.Lock()  # 登录互斥锁
```

### 工作流程

#### 1. 手动登录流程

```python
def submit_captcha(session_id, captcha_text, _internal_call=False):
    # 🔐 获取锁
    if not _internal_call:
        with self._login_lock:
            if self._login_in_progress:
                return False, "其他登录正在进行，请稍后重试"
            self._login_in_progress = True
            logger.info("🔐 开始手动登录流程")

    try:
        # ... 登录逻辑 ...
        pass
    finally:
        # 🔓 释放锁
        if not _internal_call:
            with self._login_lock:
                self._login_in_progress = False
                logger.info("🔓 手动登录流程结束")
```

#### 2. OCR 自动登录流程

```python
def _auto_login_with_ocr(max_retries=5):
    # 🔐 获取锁
    with self._login_lock:
        if self._login_in_progress:
            logger.info("⏭️ 检测到其他登录正在进行，跳过OCR自动登录")
            return False, "其他登录正在进行"
        self._login_in_progress = True
        logger.info("🔐 开始OCR自动登录流程")

    try:
        for attempt in range(max_retries):
            # ... OCR识别 ...
            # 🔥 使用内部调用，避免死锁
            login_success = self.submit_captcha(
                session_id,
                captcha_text,
                _internal_call=True  # 跳过锁检查
            )
    finally:
        # 🔓 释放锁
        with self._login_lock:
            self._login_in_progress = False
            logger.info("🔓 OCR自动登录流程结束")
```

#### 3. should_auto_login 检查

```python
def should_auto_login():
    # 1. OCR未启用
    if not self._baidu_ocr.is_enabled():
        return False

    # 2. 🔥 有登录正在进行，不要干扰
    if self._login_in_progress:
        logger.info("⏭️ 检测到登录正在进行中，跳过OCR自动登录（避免冲突）")
        return False

    # 3. 冷却期检查
    if self.is_login_recently():
        return False

    return True
```

## 🔧 技术细节

### 1. 防止死锁

**问题**：OCR 流程需要调用 `submit_captcha`，但两者都需要获取同一个锁

**解决**：

- 添加内部调用参数 `_internal_call`
- OCR 调用时设置 `_internal_call=True`
- 内部调用跳过锁检查，避免死锁

```python
# OCR调用（内部调用）
login_success = self.submit_captcha(
    session_id,
    captcha_text,
    _internal_call=True  # 🔥 跳过锁检查
)

# 用户调用（外部调用）
login_success = self.submit_captcha(
    session_id,
    captcha_text
    # _internal_call 默认为 False
)
```

### 2. 锁的粒度

- **粗粒度锁**：整个登录流程持有锁
- **优势**：简单、可靠、不会冲突
- **劣势**：登录期间其他登录完全阻塞

这是合理的，因为：

- 登录本身就应该是互斥的
- 验证码会话是唯一的
- 登录时间很短（几秒内）

### 3. 多层防护

```
第1层: should_auto_login() 检查
       ↓
第2层: _auto_login_with_ocr() 获取锁
       ↓
第3层: submit_captcha() 检查锁状态
       ↓
登录执行
```

## ⚠️ 注意事项

### 1. 锁超时

- 当前实现没有超时机制
- 如果登录流程卡住，锁会一直持有
- 但由于 finally 块保证释放，风险较低

### 2. 线程安全

- 使用 `threading.Lock()` 保证线程安全
- `_login_in_progress` 的读写都在锁内
- 避免竞态条件

### 3. 性能影响

- 锁的粒度较大（整个登录流程）
- 但登录本身就是低频操作
- 性能影响可以忽略
