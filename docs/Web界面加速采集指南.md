# Web 界面加速采集功能使用指南

## 功能概述

在 Web 界面的"完场回查"页面中，新增了**⚡ 加速采集**功能，使用 JavaScript 并发技术实现 8 倍速采集，大幅提升数据获取效率。

## 性能对比

| 模式     | 并发数        | 速度             | 采集 200 场耗时 |
| -------- | ------------- | ---------------- | --------------- |
| 标准模式 | 1             | 约 3 场/分钟     | ~70 分钟        |
| 加速模式 | 后端并发+流式 | 约 15-20 场/分钟 | **~10-15 分钟** |

**速度提升：5-6 倍！**

> **注意**：加速模式使用后端 SSE 流式 API，支持断点续传和实时进度显示。

## 使用方法

### 1. 访问完场回查页面

```
http://localhost:5001/batch-backtest
```

### 2. 选择日期范围

- **开始日期**：例如选择 `2025-11-20`（从该日期至今）
- **每天获取比赛数**：建议 50-100 场

### 3. 启动加速采集

点击 **⚡ 加速采集（8 倍速）** 按钮

### 4. 查看实时进度

系统会实时显示：

- 📊 进度条
- 📈 统计卡片（总比赛、已采集、已跳过等）
- 📝 详细日志

### 5. 采集完成后回测

点击 **🏁 开始批量回测** 进行验证

## 🎯 两种模式对比

### 🚀 标准模式（开始采集）

**特点**：

- 单线程串行采集
- 稳定可靠
- 速度较慢（约 3 场/分钟）

**适用场景**：

- 小规模采集（<50 场）
- 网络不稳定时
- 首次测试时

### ⚡ 加速模式（加速采集）

**特点**：

- 8 个任务并发
- 速度快（约 25 场/分钟）
- 自动批次管理

**适用场景**：

- 大规模采集（>100 场）
- 扩展训练样本
- 网络稳定时

**推荐使用！**

### 注意事项

1. ⚠️ **数据时效性**

   - 必发网会清空完场时间较长的比赛明细
   - **建议采集最近 7 天内的比赛**
   - 超过 7 天的数据可能大量缺失

2. 🔄 **自动跳过已采集**

   - 系统会自动识别已采集的比赛
   - 重复运行不会浪费时间
   - 可以分多次采集

3. 📊 **统计说明**
   - **已采集**：成功获取明细并缓存
   - **已跳过**：本地已有数据
   - **明细已清空**：比赛已完场但必发网清空了数据
   - **真实错误**：其他错误

## ❓ 常见问题

### Q1：为什么有些比赛明细已清空？

**A**：必发网会清空完场比赛的明细数据。建议采集最近 3-7 天的比赛。

### Q2：加速模式会不会被封 IP？

**A**：不会。8 个并发是合理范围，且每批次之间有间隔。

### Q3：可以中断后继续吗？

**A**：可以！系统会自动跳过已采集的数据。

### Q4：采集失败怎么办？

**A**：

1. 检查网络连接
2. 确认已登录必发网
3. 重新运行（自动跳过已采集）
