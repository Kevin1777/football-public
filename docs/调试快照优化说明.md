# 调试快照功能优化说明

## 📋 需求

**优化前**：

- ❌ 正常流程中频繁保存调试快照（截图和 HTML）到 `debug_html/` 文件夹
- ❌ 每个比赛采集都会生成 5-10 个调试文件
- ❌ 日志中大量"已保存调试截图"信息
- ❌ 磁盘空间占用大

**优化后**：

- ✅ 只在 **出错时** 保存调试文件到 `debug_html/` 文件夹
- ✅ 正常数据保存到 `data/` 文件夹（JSON + HTML）
- ✅ 日志简洁，不显示调试快照信息
- ✅ 磁盘空间占用显著减少

---

## 🔧 修改内容

### 1. 移除正常流程的调试快照

**文件**: `services/bifaw_client.py`

#### ❌ 已移除的调试快照

| 位置               | 原功能                      | 修改后 |
| ------------------ | --------------------------- | ------ |
| **登录检查**       | 保存登录页面截图和 HTML     | 不保存 |
| **页面打开**       | 保存明细页面初始截图和 HTML | 不保存 |
| **页面加载**       | 保存页面加载后截图和 HTML   | 不保存 |
| **关键字检测成功** | 保存检测到关键字后的截图    | 不保存 |
| **数据获取成功**   | 保存最终成功截图            | 不保存 |
| **完场回查**       | 保存完场回查页面截图和 HTML | 不保存 |

#### ✅ 保留的调试快照（仅错误时）

| 位置           | 触发条件         | 文件前缀                    |
| -------------- | ---------------- | --------------------------- |
| **登录超时**   | 登录状态验证失败 | `detail_login_timeout`      |
| **关键字超时** | 未找到关键字     | `detail_timeout`            |
| **无关键字**   | 关键字检测超时   | `detail_timeout_no_keyword` |
| **采集错误**   | 抓取过程异常     | `detail_error`              |

### 2. data 文件夹保存策略

**文件**: `backtest/detail_cache_manager.py`

#### 保存内容

每个比赛在 `data/YYYY/MM/DD/` 目录下保存：

1. **JSON 文件**（必须）

   - 交易明细数据
   - 盘口数据
   - 比赛信息
   - 元数据

2. **HTML 文件**（可选）
   - 原始页面 HTML
   - 用于后续分析或验证

#### 文件结构示例

```
data/
└── 2025/
    └── 11/
        └── 20/
            ├── 2025-11-20_英超_利物浦_vs_曼城_1530.json  ✅ 必须
            └── 2025-11-20_英超_利物浦_vs_曼城_1530.html  ✅ 新增
```

### 3. debug_html 文件夹使用策略

**只在出错时保存**：

```
debug_html/
├── detail_timeout_no_keyword_20251120_213045.html     # 关键字超时
├── detail_timeout_20251120_213045.png                 # 关键字超时截图
├── detail_error_20251120_213050.png                   # 采集错误截图
└── detail_login_timeout_20251120_213055.png           # 登录超时截图
```

## 💡 开发者指南

### 何时保存调试文件？

**只在这些情况下保存**：

1. **登录失败**

   ```python
   except TimeoutException:
       self._save_debug_screenshot(driver, prefix="detail_login_timeout")
       self._save_debug_html(page_source, prefix="detail_login_timeout")
   ```

2. **关键字超时**

   ```python
   except TimeoutException:
       self._save_debug_screenshot(driver, prefix="detail_timeout")
       self._save_debug_html(html, prefix="detail_timeout_no_keyword")
   ```

3. **采集异常**
   ```python
   except Exception as e:
       self._save_debug_screenshot(driver, prefix="detail_error")
       raise
   ```

### 如何添加新的错误处理？

```python
try:
    # 你的逻辑
    some_operation()
except SomeException as e:
    # 1. 保存调试信息
    self._save_debug_screenshot(driver, prefix="your_error_type")
    self._save_debug_html(html, prefix="your_error_type")

    # 2. 记录日志
    logger.error(f"错误描述: {e}")

    # 3. 抛出异常或返回
    raise
```

## 📝 注意事项

### 1. 调试快照截图超时

由于截图可能超时（Chrome 渲染器），已优化为：

- 超时时只记录 WARNING 日志
- 不阻塞主流程
- 不打印完整堆栈

### 2. HTML 文件大小

- 单个 HTML 文件通常 50-200KB
- 100 场比赛 ~10MB
- 建议定期清理旧数据

### 3. 错误调试文件

- 错误时的调试文件**不会自动删除**
- 需要手动清理 `debug_html/` 文件夹
- 建议保留最近 7 天的错误文件

### 4. 兼容性

- 旧版本缓存文件仍可正常读取
- 新版本同时保存 JSON 和 HTML
- 向后兼容
