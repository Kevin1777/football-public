# 前端断点续传功能说明

## 新增 UI 元素

### 1. 历史会话按钮 📋

**位置**: 完场比赛区域，日期区间采集按钮旁边  
**功能**:

- 点击查看最近 10 个采集会话
- 显示会话 ID、日期范围、进度、状态
- 可直接选择会话 ID 进行恢复

**使用方法**:

1. 点击"📋 历史会话"按钮
2. 在弹窗中查看会话列表
3. 输入想要恢复的会话 ID（或点击取消）
4. 系统自动填充会话 ID 到恢复输入框

### 2. 断点续传按钮 🔄

**位置**: 历史会话按钮旁边  
**功能**: 显示/隐藏断点续传输入区域

**使用方法**:

1. 点击"🔄 断点续传"按钮
2. 显示输入区域
3. 输入会话 ID
4. 点击"恢复采集"

### 3. 断点续传区域

**位置**: 筛选控件下方（默认隐藏）  
**包含元素**:

- **会话 ID 输入框**: 手动输入会话 ID
- **恢复采集按钮**: 开始断点续传
- **取消按钮**: 关闭输入区域
- **提示文字**: 说明如何使用

**样式**: 黄色背景，醒目提示

### 4. 当前会话信息

**位置**: 断点续传区域下方（采集开始后显示）  
**显示内容**:

- 当前会话 ID（可复制）
- 复制按钮：一键复制会话 ID

**使用场景**:

- 采集开始后自动显示
- 方便记录会话 ID
- 一键复制保存

### 5. 失败比赛列表

**位置**: 进度条下方（采集完成后自动显示）  
**显示内容**:

- 失败比赛数量
- 每场失败比赛的详细信息：
  - 比赛标签
  - 日期和时间
  - 失败原因
  - 失败时间戳
- 关闭按钮

**自动触发**:

- 采集完成且有失败比赛时自动显示
- 延迟 1 秒显示，避免闪烁

## 新增事件处理

### SSE 事件类型扩展

#### 1. `session_created`

**触发时机**: 新会话创建时  
**处理逻辑**:

- 保存会话 ID 到全局变量
- 显示当前会话信息
- 在日志中记录

#### 2. `resume`

**触发时机**: 恢复会话时  
**处理逻辑**:

- 显示恢复消息
- 更新会话 ID 显示
- 在日志中记录

#### 3. `warning`

**触发时机**: 会话恢复失败等警告  
**处理逻辑**:

- 以警告样式显示消息

#### 4. `match_skip` (增强)

**新增**: reason 字段  
**显示**: 跳过原因（已缓存/已处理）

#### 5. `match_failed`

**触发时机**: 比赛采集失败  
**处理逻辑**:

- 以错误样式记录日志

#### 6. `complete` (增强)

**新增**:

- session_id 字段
- 自动显示失败列表

## JavaScript 函数

### 1. `displaySessionId(sessionId)`

**功能**: 显示当前会话 ID  
**参数**: sessionId - 会话 ID 字符串  
**逻辑**:

```javascript
-更新显示区域的文本 - 显示会话信息卡片;
```

### 2. `copySessionId()`

**功能**: 复制会话 ID 到剪贴板  
**逻辑**:

```javascript
- 读取显示的会话ID
- 使用Clipboard API复制
- 显示成功提示
```

### 3. `loadFailedMatches(sessionId)`

**功能**: 加载并显示失败比赛列表  
**参数**: sessionId - 会话 ID 字符串  
**逻辑**:

```javascript
- 调用API获取失败列表
- 动态生成HTML列表
- 显示失败区域
- 如果没有失败，显示成功消息
```

## 用户操作流程

### 场景 1: 正常采集（新会话）

1. **选择日期**

   - 选择起始日期
   - 可选：勾选"仅显示有盘口"

2. **开始采集**

   - 点击"📥 日期区间采集"
   - 系统创建新会话
   - 显示会话 ID（可复制）

3. **监控进度**

   - 查看实时进度条
   - 查看日志输出
   - 记录会话 ID（备用）

4. **查看结果**
   - 采集完成后查看统计
   - 如有失败，自动显示失败列表
   - 查看每场失败的原因

### 场景 2: 断点续传（恢复会话）

#### 方法 A: 通过历史会话

1. **查看历史**

   - 点击"📋 历史会话"
   - 查看最近的会话列表

2. **选择会话**

   - 在弹窗中输入会话 ID
   - 或点击取消手动输入

3. **恢复采集**
   - 系统自动填充会话 ID
   - 点击"恢复采集"
   - 开始断点续传

#### 方法 B: 手动输入

1. **显示输入区**

   - 点击"🔄 断点续传"

2. **输入会话 ID**

   - 在输入框中粘贴会话 ID
   - 例如: 20251120_225830

3. **恢复采集**
   - 点击"恢复采集"
   - 系统跳过已处理比赛
   - 继续未完成的采集

### 场景 3: 查看失败详情

1. **自动显示**

   - 采集完成后自动显示（有失败时）

2. **手动查询**

   - 复制会话 ID
   - 使用 API 查询：`/api/progress/session/<id>/failed`

3. **查看详情**
   - 比赛信息
   - 失败原因
   - 失败时间

## 技术细节

### 会话 ID 格式

```
YYYYMMDD_HHMMSS
例如: 20251120_225830
```

### API 端点

1. **获取会话列表**

   ```
   GET /api/progress/sessions?limit=10
   ```

2. **获取会话详情**

   ```
   GET /api/progress/session/<session_id>
   ```

3. **获取失败列表**

   ```
   GET /api/progress/session/<session_id>/failed
   ```

4. **恢复采集**
   ```
   POST /api/collect/batch_range_stream
   Body: {
     "start_date": "2025-11-01",
     "resume_session_id": "20251120_225830",
     "filter_by_handicap": true,
     "skip_cached": true
   }
   ```

### 数据流

```
用户操作
  ↓
前端发送请求（含resume_session_id）
  ↓
后端恢复会话
  ↓
SSE流式返回
  ↓
前端实时更新UI
  ↓
显示结果和失败列表
```

## 注意事项

### ✅ 最佳实践

1. **记录会话 ID**

   - 采集开始后立即复制会话 ID
   - 保存到记事本或文档

2. **及时查看失败**

   - 采集完成后立即查看失败原因
   - 判断是否需要重试

3. **使用历史会话**
   - 忘记会话 ID 时使用"历史会话"功能
   - 查看最近的采集记录

### ⚠️ 常见问题

1. **会话 ID 无效**

   - 检查格式是否正确
   - 使用"历史会话"查看有效 ID

2. **恢复失败**

   - 确保起始日期与原会话一致
   - 检查会话状态是否为 paused 或 running

3. **失败列表为空**
   - 所有比赛都采集成功
   - 检查会话 ID 是否正确
