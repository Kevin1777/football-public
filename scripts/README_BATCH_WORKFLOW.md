# 批量回测工作流程说明

## 问题背景

必发网对**已完场比赛**不提供历史交易明细（只返回表头），因此无法直接批量回测历史完场比赛。

## 解决方案：两阶段工作流

### 阶段 1：批量采集明细（比赛前）

在比赛**开始前**抓取交易明细并保存到本地，等比赛结束后再回测。

#### 使用方法

```bash
# 采集未来1天的50场比赛（默认）
python scripts/batch_collect_details.py

# 自定义参数
python scripts/batch_collect_details.py --rows 100 --days 3 --delay 5 --output ./my_details

参数说明：
  --rows N      采集比赛数量（默认50）
  --days N      采集未来N天的比赛（默认1天）
  --delay N     请求间隔秒数（默认3秒，避免频繁请求）
  --output DIR  输出目录（默认: collected_details/）
```

#### 采集内容

每场比赛保存为独立 JSON 文件，包含：

- `match_info`: 比赛基本信息（球队、时间、联赛）
- `trade_data`: 交易明细数据（UG-PDF）
- `handicap_data`: 让球盘口数据
- `metadata`: 元数据
- `collected_at`: 采集时间

#### 文件命名

格式：`YYYYMMDD_比赛ID_时间戳.json`

示例：`20251120_曼联_vs_利物浦_03-00_20251119_143052.json`

---

### 阶段 2：批量回测（比赛后）

等比赛结束后，从本地文件读取明细进行批量回测。

#### 使用方法

```bash
# 回测collected_details/目录中的所有比赛（默认）
python scripts/batch_backtest_from_local.py

# 指定输入目录
python scripts/batch_backtest_from_local.py --input ./my_details

参数说明：
  --input DIR  明细文件目录（默认: collected_details/）
```

#### 回测流程

1. 读取本地 JSON 文件
2. 重建交易明细 DataFrame
3. 从 500 彩票网查询实际比分
4. 调用推荐引擎生成推荐
5. 验证推荐结果
6. 生成回测报告

#### 输出内容

- **终端输出**: 每场比赛的回测结果
- **文本报告**: `backtest_report_YYYYMMDD_HHMMSS.txt`
- **JSON 结果**: `backtest_results_YYYYMMDD_HHMMSS.json`（详细数据）
- **日志文件**: `batch_backtest.log`

## 注意事项

### ⚠️ 采集阶段

1. **时机重要**: 必须在比赛**开始前**采集（一旦比赛结束，必发网会清空明细）
2. **请求频率**: 建议设置 `--delay 3`（3 秒间隔），避免被封 IP
3. **数据验证**: 检查采集日志，确认明细行数正常（通常>100 行）
4. **定期清理**: `collected_details/` 目录会不断增大，定期备份并清理

### ⚠️ 回测阶段

1. **比赛完场**: 确保所有比赛已结束，否则查询不到比分
2. **时差问题**: 比赛结束后等待 1-2 小时再回测，等数据同步
3. **失败处理**: 部分比赛可能查询不到比分（杯赛、小联赛），属于正常情况

## 与原有回测的区别

| 功能         | 原回测 (app.py)         | 新工作流          |
| ------------ | ----------------------- | ----------------- |
| **数据来源** | 实时抓取（已失效）      | 本地文件          |
| **适用场景** | 已完场比赛（❌ 不可用） | 提前采集+事后回测 |
| **速度**     | 慢（每场需抓取）        | 快（本地读取）    |
| **成功率**   | 0%（无数据）            | 高（提前采集）    |

```bash
# 每天凌晨采集当天和次日比赛
0 0 * * * cd /path/to/project && python scripts/batch_collect_details.py --days 2 >> collect.log 2>&1
```

### 自动化工作流

```bash
#!/bin/bash
# auto_backtest.sh

# 1. 每周五采集周末比赛
if [ $(date +%u) -eq 5 ]; then
```

## 故障排查

### 问题 1: 采集时解析失败

**现象**: `❌ 解析失败: 未能从网页表格中识别有效数据`

**原因**:

- 比赛已完场（明细已清空）
- 网络问题导致页面未完全加载

**解决**:

- 确认比赛尚未开始
- 检查 `debug_html/` 中保存的 HTML 文件
- 增加 `--delay` 间隔时间

### 问题 2: 回测时查询不到比分

**现象**: `⚠️ 未查询到比分，可能比赛未结束`

**原因**:

- 比赛尚未结束
- 比赛被推迟/取消
- 500 彩票网尚未更新数据

**解决**:

- 等待 1-2 小时后重新回测
- 检查比赛是否真的结束
- 手动查询 500 彩票网确认

### 问题 3: 采集速度慢

**解决**:

- 减少 `--rows` 数量
- 使用多进程（需自行实现）
- 只采集重点联赛（需修改代码过滤）

## 数据存储管理

### 目录结构

```
collected_details/
├── 20251120_曼联_vs_利物浦_20251119_143052.json
├── 20251120_皇马_vs_巴萨_20251119_143215.json
├── ...
└── archived/  (可选，存放已回测的文件)
    ├── 20251113_...json
    └── ...
```

### 磁盘占用

- 每个 JSON 文件约 50-200KB
- 100 场比赛约 10-15MB
- 建议每月备份并清理
