# 完场回查使用说明

## 参数说明

### `--days` 参数（往前推天数）

- `--days 0`：**仅今天**的比赛
- `--days 1`：**今天+昨天**的比赛（默认）
- `--days 2`：**今天+昨天+前天**的比赛
- `--days 7`：**过去 7 天**（今天往前推 7 天）

## 使用场景

### 场景 1：查看昨天完场比赛列表

```bash
# 获取昨天的完场比赛（今天+昨天，自动过滤出昨天已完场的）
python scripts/batch_collect_details.py --days 1 --rows 100
```

**说明**：

- 虽然会获取今天+昨天的比赛列表
- 但**昨天完场比赛的明细已被清空**（必发网限制）
- 采集时会显示 "解析失败：未能从网页表格中识别有效数据"
- 仍会保存比赛信息和盘口数据到 JSON（但交易明细为空）

---

### 场景 2：采集今天正在进行的比赛

```bash
# 仅今天的比赛（可能有明细数据）
python scripts/batch_collect_details.py --days 0 --rows 50
```

**最佳实践**：

- 在比赛**进行中**采集，明细数据完整
- 比赛结束后 1-2 小时内采集，部分明细可能仍存在
- 比赛结束超过数小时，明细大概率已被清空

---

### 场景 3：采集过去一周的比赛列表（含盘口）

```bash
# 过去7天的比赛（明细可能已清空，但可获取比赛列表和盘口）
python scripts/batch_collect_details.py --days 7 --rows 200
```

**用途**：

- 获取完场比赛的基本信息
- 获取让球盘口数据（可用于分析）
- 交易明细大概率已被清空

---

## 完场比赛限制说明

### ⚠️ 必发网数据保留策略

| 时间                  | 比赛列表  | 让球盘口  | 交易明细      |
| --------------------- | --------- | --------- | ------------- |
| **比赛进行中**        | ✅ 可获取 | ✅ 可获取 | ✅ **可获取** |
| **比赛结束 1 小时内** | ✅ 可获取 | ✅ 可获取 | ⚠️ 部分可获取 |
| **比赛结束数小时后**  | ✅ 可获取 | ✅ 可获取 | ❌ **已清空** |
| **比赛结束 1 天以上** | ✅ 可获取 | ✅ 可获取 | ❌ **已清空** |

## 推荐工作流

### 方案 A：实时采集（推荐）

适合需要**完整交易明细**的回测：

```bash
# 1. 每天采集当天比赛（比赛进行中）
python scripts/batch_collect_details.py --days 0 --rows 50

# 2. 等比赛全部结束后回测
python scripts/batch_backtest_from_local.py
```

**优点**：

- 交易明细完整
- 回测结果准确

**缺点**：

- 需要在比赛进行时运行
- 需要定时任务或人工触发

---

### 方案 B：定时任务（自动化）

设置定时任务，自动采集：

```bash
# Linux/Mac (crontab -e)
# 每2小时采集一次当天比赛
0 */2 * * * cd /path/to/project && python scripts/batch_collect_details.py --days 0 >> collect.log 2>&1

# Windows (任务计划程序)
# 每2小时运行：batch_collect_details.py --days 0
```

---

### 方案 C：完场回查（仅元数据）

适合只需要**比赛列表和盘口**，不需要明细：

```bash
# 查看过去7天的比赛和盘口
python scripts/batch_collect_details.py --days 7 --rows 200
```

**可用数据**：

- ✅ 比赛基本信息（主客队、时间、联赛）
- ✅ 让球盘口数据
- ❌ 交易明细（已被清空）

**用途**：

- 统计盘口分布
- 分析赛程安排
- 标注比赛标签
- **无法用于推荐引擎回测**（缺少交易明细）

## 常见问题

### Q1: 为什么采集昨天的比赛提示"解析失败"？

**A**: 完场比赛的交易明细已被必发网清空，这是正常现象。如需完整数据，请在比赛进行中采集。

---

### Q2: 如何判断明细是否已被清空？

**A**: 查看 JSON 文件中的 `trade_data.shape`：

```json
{
  "trade_data": {
    "shape": [0, 0] // 0行0列 = 明细已清空
  }
}
```

或查看采集日志：

```
❌ 解析失败: 解析失败：未能从网页表格中识别有效数据。
```

---

### Q3: 能否从其他网站获取历史明细？

**A**: 目前实现的采集器仅支持必发网。其他数据源需要：

1. 新增对应的客户端（如 `OtherSiteClient`）
2. 适配数据格式
3. 修改采集脚本调用新客户端

---

### Q4: 采集失败率很高怎么办？

**可能原因**：

1. **比赛已完场** → 明细被清空（正常现象）
2. **网络问题** → 检查网络连接，增加 `--delay` 间隔
3. **被封 IP** → 减少并发，增加请求间隔
4. **登录过期** → 重新登录必发网

**调试方法**：

```bash
# 查看详细日志
python scripts/batch_collect_details.py --days 0 --rows 10 2>&1 | tee debug.log

# 检查保存的HTML文件
ls -lh debug_html/*.html
```

## 总结

| 需求             | 推荐方案         | 命令示例              |
| ---------------- | ---------------- | --------------------- |
| **完整回测**     | 实时采集当天比赛 | `--days 0 --rows 50`  |
| **查看完场列表** | 回查过去几天     | `--days 7 --rows 200` |
| **定时自动化**   | cron/任务计划    | 每 2 小时运行一次     |
| **小规模测试**   | 采集 10 场验证   | `--days 0 --rows 10`  |

**关键点**：

- ✅ 比赛进行中采集 → 明细完整
- ❌ 比赛结束后采集 → 明细已清空
- ⚠️ 完场回查只能获取元数据，无法用于推荐引擎回测
